# 薄肌教练排行榜

排行榜是可选功能。只有用户明确同意加入并上传分数时才使用。没有参与任何排行榜时，仍按 `scoring.md` 的已确认默认规则在本地打饮食分、运动分和薄肌分，但不调用排行榜 MCP，也不上传分数。原始饮食、训练、体重、照片和健康数据继续留在本地 `baoji/`；MCP 只接收排行榜成员标识、0–100 分、规则版本和幂等键。

## 加入与本地缓存

- 选榜靠名字：用户说要加入哪个排行榜，就把他说的名字传给 `join_leaderboard` 的 `name`；用户没说具体哪个，就用默认的「薄肌教练排行榜」。名字不区分大小写和前后空格。
- 找不到（`NOT_FOUND`）：告诉用户没找到这个名字的排行榜，请他核对一下名字；或者问他要不要用这个名字新建一个。
- 排行榜 ID 只给你自己用：`join_leaderboard` 返回的 `leaderboard_id` 存进本地状态，之后提交、取规则时用它；不要把 ID、链接或文件路径说给用户，对用户只说排行榜的名字。
- 身份：排行榜 MCP 用 OAuth 登录（用户的 openTag 账号），服务端从登录得到用户身份，工具里没有身份参数。MCP 还没授权时，按平台提示让用户完成授权，再继续。
- `display_name`：先看 `baoji/profile.md` 和 `baoji/leaderboard-state.json` 里有没有已确认的昵称，有就直接用，不再问；没有才问一次用户想在榜上显示什么昵称（不默认用真名），问到后马上写进 `profile.md`。

用户同意加入后，调用 `join_leaderboard`，再调用一次 `get_leaderboard_definition`。把 membership 和完整 definition 写入本地 `baoji/leaderboard-state.json`，至少保存：

- 排行榜名字、`leaderboard_id`、`display_name`、`membership_id` 和 membership `status`；
- definition 的 `timezone`、`current_cycle_start`、`next_cycle_start`、全部维度、自然语言标准和 `criteria_version_id`；
- `cached_at`，只用于排查缓存，不作为服务端归档时间。

每个排行榜分别缓存。同一 `current_cycle_start` 周期内直接复用，不在一日三餐、每次训练或每次重算前重复调用 `get_leaderboard_definition`。令牌和原始健康数据都不要写入这个文件。用户离开后把本地 membership 标为 `left`，后续不再调用该排行榜 MCP 或上传分数。

## 打卡与提交

1. 每次餐食或训练打卡，依据本地记录和缓存标准即时更新当天的 0–100 分，不调用 MCP。MCP 负责分发规则和存分，不替你计算热量、步数、体重变化等原始健康指标。
2. 资料不足时先问用户。仍不足就不猜、不把未知记成 0，也不要提交当天分数。
3. 在同一周期提交时，使用缓存中的全部维度和 `criteria_version_id`。到缓存的 `next_cycle_start` 后，先调用一次 `get_leaderboard_definition` 刷新缓存，再进行新周期首次提交。
4. 用 `submit_daily_update` 一次提交当前全部维度。每份新分数生成一个新的 `idempotency_key`；如果调用超时或结果不明，用同一个 key 和同样的分数重试，不要换 key。不传日期或时区；服务端按排行榜唯一时区归档，当天再次提交会覆盖当天最终分数。
5. 如果提交返回 `STALE_CRITERIA`，立即调用一次 `get_leaderboard_definition`，覆盖旧缓存，按新标准重新计算全部维度，并用新的幂等键重提。若刷新后仍返回 stale，停止重试并报告服务端规则状态异常。

## 已确认默认规则

### 饮食分

- 按用户已确认的个性化饮食计划、目标和现实约束评分，不套统一热量或禁忌。
- 明显不健康行为发生时，饮食分最高 50 分。

### 运动分

- 按用户已确认的训练、活动和恢复计划评分。
- 计划休息日默认 60 分；如果按计划完成主动恢复，可以依规则上调。
- 明显不健康行为发生时，运动分最高 50 分。

### 薄肌分

- 默认 `四舍五入(饮食分 × 50% + 运动分 × 50%)`。
- 任一组成分未知时不要提交薄肌分。
- 出现明显不健康行为时，相关单项以及薄肌分最高 50 分。

这些是已确认的默认规则。排行榜创建者可以用一段自然语言发布新版标准；新版只从下一周周期生效。参与排行榜时以当前周期缓存的 MCP definition 为准，并按上面的周期边界和 stale 响应刷新；不要每次打分都拉取。

## 创建者

用户想自己建一个排行榜时，先问他起什么名字，用 `create_leaderboard`，当前登录的用户就是创建者；建好后用户自己也要 `join_leaderboard` 才会上榜。名字已被占用（`NAME_TAKEN`）时，请用户换个名字，或者问他是不是想加入那个已有的排行榜。告诉用户：朋友只要跟自己的助手说出这个排行榜的名字就能加入，由用户决定告诉谁。只有创建者能用 `add_dimension` 和 `update_scoring_criteria`，新维度和新标准都从下一周期生效。

## 排名

- 日榜使用当天最后一次提交后的最终分。
- 周榜把本周每一天的最终分累计起来，不求平均。
- 默认查看薄肌分，也可以指定其他维度。

分数只用于趋势和轻量互动，不是健康诊断或人格评价。出现进食障碍迹象时停用评分，不上传分数，并建议寻求专业帮助。
